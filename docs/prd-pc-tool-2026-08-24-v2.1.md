## 1. 产品目标（3 个正交目标 + 量化退出标准）

**O1 · 可验证的安全感（Trust & Safety）**：建立「零广告、零捆绑、默认零数据外传」准入基线，把「隐私」翻译成可验证的安全感——🟢 直清可重建垃圾、🟡/🔴 删除默认进隔离区（14 天可一键还原）、全程操作透明日志、规则外置可审计、安全分级强制人工确认。这是与 360/腾讯/联想管家/CCleaner 的根本区隔。

- **退出标准**：
  - **M6** 用户体验后「可验证安全感」问卷评分 **≥4.2/5**（≥15 人深度访谈 + 问卷 NPS 辅证；信任行为指标——完成清理后主动查看日志/隔离区的比例 ≥40%）；
  - **M7** 首次使用后 7 日内**信任转化率 ≥60%**（完成一次清理并主动二次打开工具；若实测基线偏低，MVP 目标可先定 40–50%）；
  - **M8** 破坏性操作**日志覆盖率 100%**（每一次删除均可追溯路径/时间/结果/去向）；
  - **M2（分档）** 误删率：**🟢<0.5% / 🟡<2% / 🔴 零容忍（任一红档误删即阻塞发布）**；
  - **M12（v2.1 新增）** 隔离区**还原成功率 ≥99.9%**（1000 次还原测试 ≤1 次失败；失败须有兜底指引）——隔离区成为回退承诺底座后，还原失败比误删更伤信任，须以硬门禁守护。

**O2 · 低门槛的有效清理（Effective & Low-friction）**：让非计算机专业学生（主 Persona 小林）无需理解晦涩规则也能安全释放空间、管理自启。

- **退出标准**：普通模式覆盖率 ≥80%（M4）、全盘扫描 ≤120s@1TB（M3）、误删/回退率达标（M2 分档 + M12）、R21 测试体系覆盖黄金文件集 + VM 快照回归（否则 M2/M12 度量口径为空话）。

**O3 · 可解释与差异化（Explainable & Differentiated）**：通过「清理项可解释 + 端侧中文意图搜索（远期）+ 规则外置可扩展」建立竞品空白区差异化；以模块化、轻量（<20MB）与开源可信构建护城河。

- **退出标准**：
  - **M9** 端侧中文意图准确率 **≥90%**（R17 沙盒验证达标才默认开）；
  - **M10** 规则可扩展性：社区贡献规则数（开源后，阶段三追踪）；
  - 安装包 **<20MB** 与 **M11-L 轻量审计通过**（源码公开 + 数据流向图 + 抓包验证方法 + opt-in 默认值审计；M11-F 完整第三方审计为阶段三目标）。

> 三目标正交：O1 管「信任与不出事」，O2 管「普通用户用得爽且有效」，O3 管「凭什么赢且能持续」。

> **指标分层对齐**：**MVP 硬门禁**：M2(分档)/M3/M4/M8/**M12**/M11-L/R21 测试覆盖；**MVP 观测项**：M1/M5/M6/M7；**阶段二/三**：M9/M10/M11-F。

## 2. 用户故事（场景）

1. **小林｜盘满告警**：C 盘飘红不敢更新，打开 PureSlate 点「一键体检」→ 只读扫描给出「可释放约 X GB」报告，逐项列临时/大/重复文件并标风险；勾选绿色项确认后**直清（可重建的临时垃圾）**，**C 盘立即回落**；谨慎项（微信缓存）进入隔离区，14 天内可一键还原。无弹窗无捆绑。
2. **小林｜开机变慢**：进「启动项」页，列表按影响排序并显示发布者与建议，禁用 3 个不认识的自启，重启后明显加快。
3. **小林｜借出前清隐私**：运行「隐私清理」，逐项列浏览器历史/表单/最近文档并标「删了什么、能否恢复」，确认后执行进隔离区（回退可控），事后在操作日志看到完整记录，获得踏实感。
4. **阿杰｜可审计定制清理**：打开规则视图看每条清理规则的外置 XML 与匹配逻辑，对比方案 A/B 取舍后手动勾选，日志核对每一步；可导入社区规则但不触发自动删除。
5. **阿杰｜中文找功能（远期）**：搜索框输「微信占了我多少空间」，端侧中文意图解析直接定位微信缓存清理项并给预估释放量（非翻菜单）。

## 3. 用户研究洞察（来自瑞思）

- **主 Persona 小林**：大三、非计算机专业、C/D 盘常年 ~75% 满载；反感 360/腾讯/联想管家弹窗与全家桶；不信任 CCleaner（供应链投毒+遥测史）；现手动用「火绒 + Dism++」但嫌 Dism++ 规则晦涩；「能用好工具、写不出工具」的小白。
- **次 Persona 阿杰**：计算机相关学生、鸿蒙 App 开发者；要可审计/可配置/规则外置；拒绝一键盲删；习惯方案对比 + 权衡分析。

**行为特征与决策路径（假设性，非实测，待 5.1 校准）**
- **小林**：被动型清理（每 2–3 周，仅盘满后才动）；典型路径「看到红条 → 打开 Dism++ → 面对规则犹豫 → 百度搜哪些能勾 → 只敢勾临时文件」。一天场景：期末赶作业 C 盘飘红，要「一键帮我看能安全删什么」而非「一堆规则」。
- **阿杰**：主动型（每月 2–3 次）；装新软件后必查自启；路径「装软件 → 查自启 → 读规则 XML → 手动执行 → 验证」。

> **Storage Sense 追问**：小林为何不用系统自带 Storage Sense？主因「不知情 + 功能弱（无大文件/重复文件扫描、无可解释报告）」——PureSlate 差异化落点，见第 4 章。

**需求层次**：Must-have = 空间清理（只读+可选+可审计）、启动项管理、隐私清理（逐项确认）、安全分级机制。Should-have = 第三方弹窗拦截、应用缓存清理、轻量外壳、清理项可解释、一键体检报告。Nice-to-have = 端侧中文搜索意图、多设备同步、规则市场、硬件看板（v2.1 移阶段二）。

**关键洞察**：① 无广告无捆绑是**准入门槛而非卖点**；② 隐私要转成「**可验证的安全感**」；③ 轻量与零学习成本权重**高于功能广度**；④「**只读 + 人工确认**」是差异化护城河；⑤ 方案对比型决策要「**给选项不给结论**」。  
**风险陷阱**：过度设计/功能蔓延；忽视安全分级致误删；把开发者当全体用户；低估可信度建设；过早承诺端侧 AI；把对标做成照搬。

**为何不用系统自带的 Storage Sense**
1. **能力弱项**：只清临时文件/回收站/下载旧文件，**无大文件（≥500MB）扫描、无重复文件 hash、无可解释报告**——正是小林「盘满告警」最需要的。
2. **不可审计/不可控**：规则固定黑盒，用户无法看「删什么、为什么」——与 O1 相悖。
3. **无跨场景整合**：启动项、隐私、缓存分散在各面板，PureSlate 用统一报告 + 🟢🟡🔴 分级一次呈现。  
→ PureSlate 在「可解释 + 可扩展 + 大文件/重复文件扫描」维度建立不可替代性。

**4 条差异化切口**：① 规则外置 + 端侧中文意图搜索（核心）；② 学生向隐私优先 + 默认零外传（信任）；③ 轻量原生壳 + 模块化（体验）；④ 规则社区化 + 开源可信（生态）。**卖点排序**：隐私优先 > 端侧中文语义 > 轻量可裁剪 > 规则可扩展。

### 6.1 安全分级规则表（R02 判定标准）

分级由 `rule_engine` 依据规则 XML 中声明的 `risk_level` 字段自动判定；**无法判定时默认 🔴（保守原则）**。判定三维度：**可逆性 × 影响面 × 误删后果**。

| 档位 | 判定维度 | 典型特征 | 示例 | 默认交互 | **去向（v2.1）** |
| --- | --- | --- | --- | --- | --- |
| 🟢 安全 | 可逆性=极高；影响面=无；误删后果=无 | 删了随时回来或本就该删 | %temp%、回收站内容、浏览器缓存、缩略图缓存 | 普通模式默认可勾 | **直清或系统回收站（立即释放）** |
| 🟡 谨慎 | 可逆性=中；影响面=单应用；误删后果=轻微 | 清了能恢复但有点麻烦 | 应用缓存（微信/QQ）、聊天媒体、下载目录大文件 | 默认展开待确认 | **隔离区（14 天可还原）** |
| 🔴 危险 | 可逆性=低/不可逆；影响面=系统/多应用；误删后果=严重 | 删了可能开不了机或丢重要资料 | 注册表项、系统文件、用户文档、驱动 | 灰禁+二次确认+专家模式；白名单保护 | **隔离区（14 天可还原）** |

> **M2 分档映射**：🟢 类误删率目标 <0.5%；🟡 类 <2%；🔴 类**零容忍（任一红档误删即阻塞发布）**。白名单：系统目录、在用文件、个人目录默认进 🔴 须显式确认。

### 6.2 隔离区生命周期规格（v2.1 新增 · R25 细化，解决空间释放悖论）

> **背景**：v2.0 的隔离区只有「移入 + manifest + 还原」，缺生命周期后半段——文件移入同盘隔离区**不释放任何空间**，与用户故事「清理后 C 盘回落」矛盾。本节补全。

**设计原则**：信任需求（可回退）与空间需求（立即释放）**分级各归其位**，空间语义全程透明。

1. **分级去向**：
   - 🟢 类（临时文件/回收站内容/浏览器缓存等可重建垃圾）→ **直清或系统回收站**，立即释放空间——无须隔离占盘；
   - 🟡/🔴 类（应用缓存/聊天媒体/隐私痕迹等）→ **隔离区**，14 天保留期内可一键还原。
2. **保留期**：默认 **14 天**（可配置 7–30 天）；**到期前 3 天**首页通知；到期**自动清除**（真正释放空间）并写日志（M8）。
3. **容量上限**：隔离区上限 = min(5GB, 所在盘剩余空间 10%)；超限时提示用户「确认释放最早批次」，不静默丢弃。
4. **显式确认释放**：隔离区管理页提供「确认清空」入口 + 二次确认；清空即硬删并写日志。
5. **空间语义透明（关键）**：报告页/完成页/隔离区管理页**严格区分**「**已释放 X GB**」（直清/回收站）与「**已隔离 Y GB（尚未释放）**」——绝不让用户误以为隔离=释放。
6. **manifest 字段**：原路径/大小/移入时间/内容哈希/来源分级/还原状态。
7. **还原兜底**：还原遇原路径被占用/权限变化 → 还原到「还原冲突」目录并明确告知，计 M12 分母；还原成功率 **≥99.9%**（1000 次测试 ≤1 失败）。
8. **验证**（9.7 实验B）：内测观察「确认清空」使用率与「为什么清了没释放空间」困惑率；失败信号：>30% 用户困惑 → 调整为 🟢 默认直清 + 更强引导。

## 8. Non-goals（明确不做什么）

- **NG1** 不做杀毒/实时防毒引擎——火绒已占安静心智，避免功能蔓延。

- **NG5** MVP 不做端侧中文 AI 搜索——待准确率验证后再定。
- **NG6** 不做跨端（手机/平板）清理——本期仅 Windows PC。
- **NG7** 不做账号体系/云存储/远程控制——坚守默认零数据外传（更新检查/崩溃报告仅 opt-in，见 8.5）。

## 8.5 遥测与数据外传原则（默认零 + 显式 opt-in）

> 「零遥测」的**精确化**：清理工具必然要「检查更新」与「崩溃排障」，笼统说「零联网/零遥测」会与工程事实自相矛盾。采用行业通行原则：**默认零数据外传 + 显式 opt-in + 内容可审查**。

**原则声明**：PureSlate **默认不向任何服务器发送可识别用户的数据**。仅以下两类网络/文件行为存在，且**均须用户显式 opt-in、内容可审查**：

1. **更新机制（落 R22）**：默认手动「检查更新」；opt-in 后每周静默查一次版本号（GitHub API，请求不含任何用户标识/设备指纹/清理结果）；规则包走 GitHub Releases，manifest 带 hash 校验。
2. **崩溃处理（落 R24）**：本地始终写 minidump（仅落盘不外发）；opt-in 上传前先展示内容预览，用户确认后才传；排障主通道 = R09 日志导出 + GitHub issue 模板。

3. **表述精确化**：全文「零遥测」一律指「**默认零数据外传；更新检查与崩溃报告均显式 opt-in、内容可审查**」。README 数据流向图按此绘制。M11-L（MVP 门禁）据此定义验收；M11-F 完整审计为阶段三。

> 该原则已「决策已定」，不再列入第 10 章待确认。**不新增第三类上报行为**（v2.1 修正风险 5 残留表述：M5 度量以本地日志统计 + 内测访谈 + 社区 issue 采样完成）。
