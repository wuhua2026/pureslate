> 评审方式：人类以无上下文新会话对照本文评审代码。假设有第二双眼睛专挑问题。
> 本任务核心矛盾：要清理的安装目录残留位于 §2.2 程序目录白名单（"永远不得进入删除候选"）。

## 二、破坏面清单

本次新增/改动的所有"能删文件/移动文件/写注册表/杀进程"路径（逐条）：

1. **残留文件 → 隔离区**：复用既有 `cleaner::execute::apply_one → quarantine::move_into_quarantine`（同盘 rename/跨盘 copy+fsync+hash 校验后删源 + manifest + journal）。无新删除原语。
2. **残留文件 → 直接删除**：复用既有 `delete_direct`（`DeleteFileW`，绕过回收站）。新增的只是"在什么前提下这条既有路径可达"——见下方六前提。
3. **空目录收尾 `remove_empty_dir` → `RemoveDirectoryW`**：Win32 语义保证**仅空目录成功**；非空/有句柄占用静默失败；不递归、不枚举内容；调用前候选内所有文件已经过 journal 事务处理。这是本任务唯一新增的 OS 删除调用，删除面严格限定为空目录。
4. **枚举只读**：`std::fs::symlink_metadata/metadata/read_dir`、walkdir（follow_links=false）。零写、零注册表读写（上下文来自 R27-2 已读的 InstallLocation 内存值）。
5. **注册表**：本任务零注册表调用（R27-3 不新增任何 Reg* API）。
6. **进程**：零 TerminateProcess/open-kill；guard 仅 Toolhelp 只读快照；取消复用 clean CancelToken（停等待）。
7. **还原开口**：`restore_one` 对软根的白名单拒绝放宽，但仅认 manifest 里的 `category=residue.uninstall`，且：隔离文件必须在隔离区根内、sha256 与 manifest 一致、硬保护仍拦、父链无 reparse、原路径存在则落 restore-conflict 不覆盖、父目录 create_dir_all 重建。

### §2.2 开口的六重前提（评审请逐条挑错，对应 SAFETY §2.2 R27-3 条款）

| # | 前提 | 代码位置 | 失效后果 |
|---|------|----------|----------|
| ① | 必须有最近 removed/reboot_pending 卸载上下文；无上下文命令直接 Err | commands `uninstall_residue_scan` 读 `state.last_uninstall` | 无卸载即无残留入口，无法无中生有扫描 PF |
| ② | 候选 id 必须出自后端最近扫描快照；快照 clean 时一次性 take | `state.residue_snapshot` + `prepare_targets` find(id) | 前端传任意 id/路径 → "候选不在最近扫描结果中"拒绝 |
| ③ | 路径必须段级位于该组精确授权根内 | preflight `is_within(p, authorized_root)` | 授权 A 目录删不到 A 外任何文件 |
| ④ | 硬保护/reparse/TOCTOU 不绕过；候选根双安全闸 | preflight verify 全序列 + install_root_safety/asserted_root_safety + collect_files 计 reparse 点 | Windows/引导卷/XML 根/卷根/Users 浅层/共享目录名/junction 全部拒 |
| ⑤ | direct 须专家模式一次性令牌；默认恒 quarantine | commands `uninstall_residue_clean` has_direct→consume_pending_confirm；UI 仅专家可签 | 非专家/无 token/复用 token → 命令 Err，不落盘 |
| ⑥ | 组内 .exe 任一在运行 → 整组跳过（快照放回） | prepare_targets `guard::any_running(exes)` | 运行中的程序残留不半清 |

额外护栏：
- **误报方向**：名称只精确匹配（归一后相等），通用产品名（update/cache/runtime/tools…）与共享段（windows/common files/programs/appdata/local…）双拒绝名单；厂商程序组必须内含产品名快捷方式才收；AppData 厂商目录只收匹配产品名的子目录，绝不整收。
- **候选爆炸**：单根 20,000 文件 / 10 GiB / 深度 20，超限整组放弃（InstallLocation 被篡成卷根/巨型树时自我保护）。
- **去向白名单**：后端只接受 quarantine/direct，recycle 入参即 Err。
- **审计**：文件级 op=clean + category=residue.uninstall + disposition + 成败，M8=100% 口径不破。
- **红线 6**：新增生产代码无 unwrap/expect/panic（锁中毒均 into_inner 或失败关闭）。

### 残留风险（如实声明）

1. **名称精确匹配的两端**：版本号格式奇异（如 `App 2024 R2`）可能漏匹配（偏保守=少删，可接受）；两个不同软件恰用同一归一产品名（如都叫 "Tool"，已被通用名名单拦）仍可能误并列——UI 逐项 + 理由 + 默认隔离可还原兜底。
2. **InstallLocation 被软件写成非标准值**：严格闸可能拒绝合法但路径浅/共享名的目录（宁可不列）；被列目录仍可能含共享文件——默认隔离区 14 天还原是最终安全网。
3. **reboot_pending 后扫描**：待重启删除的文件在重启前仍在，枚举可能重复列入；用户在提示重启后执行属小概率，direct 时由 OS 占用/不存在返回失败可见。
4. **真机命中率未知**：三源启发式（尤其厂商名归一覆盖法人后缀的有限名单、开始菜单两层深度）需真机样本校准；已在 TASKS 备注挂人类走查（Inno/NSIS/MSI 各类 ≥3，重点看厂商组与 AppData 同名误报）。
