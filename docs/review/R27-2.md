## 二、破坏面清单

逐条列出本次改动中所有"能创建/终止进程、能读写注册表、能增删文件"的代码路径：

### A. 进程面（本任务唯一的主动 OS 动作 = 创建进程）

1. **`runner::launch` → `CreateProcessW`**：创建第三方官方卸载器进程。最小化参数：
   `lpApplicationName=NULL`、`bInheritHandles=FALSE`（**不继承本进程任何句柄**）、
   `dwCreationFlags=0`（无 CREATE_SUSPENDED、无提权标志、不绑定 Job Object 杀组）、
   `lpEnvironment=NULL`（继承环境）、`lpCurrentDirectory=exe 父目录`（PATH 命令如 msiexec 给 NULL）；
   命令行 exe 部分**恒定加双引号**，参数原样透传；**不经 cmd.exe/任何 shell**，
   命令行直交内核解析 → 不存在 shell 元字符注入面。
2. **`runner::launch_runas` → `ShellExecuteExW(verb="runas")`**：**仅在** CreateProcessW
   返回 `ERROR_ELEVATION_REQUIRED(740)` 时到达；弹 Windows 标准 UAC，用户拒绝/关闭 →
   返回 Err（launch_failed），**无任何绕过 UAC 的降级路径**；同样设 NOCLOSEPROCESS + cwd。
3. **`wait_tree` → `WaitForSingleObject`/`CreateToolhelp32Snapshot`/`Process32*`**：
   只等待、只读快照。**全代码库无 `TerminateProcess`、无 `OpenProcess(PROCESS_TERMINATE)`、
   无 `GenerateConsoleCtrlEvent`**；取消 = `CancelToken`（AtomicBool）置位，
   等待循环 250ms 粒度退出，**不向卸载器发任何信号**（SPEC §6.7 硬约束）。
4. **`exit_code` → `GetExitCodeProcess`、`pid_from_handle` → `GetProcessId`**：只读；
   259(STILL_ACTIVE) 视为未知（None）。
5. **`CloseHandle`**（ProcessInformation/Snap 的 Drop）：只关本任务创建的句柄。

### B. 注册表面（零写）

6. **`pending_reboot_entries`**：只读打开 `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager`
   并读 `PendingFileRenameOperations`（标准用户可读；失败/键缺/类型不符→空 Vec，容错不阻断）。
7. **`run_app_uninstall` 前后两次 `list_apps()`**：R27-1 既有只读枚举（四视图 KEY_READ）。
8. **全任务无 `RegSetValueEx`/`RegDeleteKey`/任何 HKEY 写句柄**（可 grep 复核）。

### C. 文件系统面（零删零移）

9. 无 `DeleteFileW`/`MoveFileW`/`SHFileOperation`/拷贝；仅 `Path::exists()` 只读探测、
   `GetLongPathNameW`/`ExpandEnvironmentStringsW` 只读字符串转换。
10. **无 SeDebugPrivilege / `AdjustTokenPrivileges`**（可 grep 复核）。

### D. 审计面（既有设施，仅追加文本）

11. `audit::record` op=`uninstall`：start（含命令行）→ 终态
    （removed/reboot_pending/still_present/timeout/cancelled/launch_failed，含退出码警告）。
    审计写入失败不阻断主流程（与既有各 op 同语义）。

### E. 信任边界声明（破坏主体外移）

12. 真正的删除动作发生在**第三方卸载器自己的进程内**，不在 PureSlate 进程、
    不经本应用 journal/隔离区、不可由本应用还原。Apps.vue 确认面板在按钮点击前明示三条：
    ①将调起程序自带官方卸载器并需用户在其窗口手动完成；②其删除不经过本应用隔离区/日志、
    无法由本应用还原；③本应用只拉起/等待/核对，不强杀进程。执行按钮文案为
    「我已了解，调起官方卸载器」（知情同意，非默认继续）。

### 护栏对照表（评审请逐条挑错）

| 风险 | 护栏 |
|------|------|
| 命令源被污染 | UninstallString 数据源 = 系统"程序和功能"同源的 HKLM/HKCU Uninstall 键；用户自行安装的程序本就具备同等登记能力，未新增提权面；且只取**交互串**（修复了 Quiet 误取），SW_SHOWNORMAL 强制官方 UI 可见 |
| 命令构造 | 空白/未闭合引号→`split_exe_args` 返回 None→拒绝拉起；exe 恒引号；参数不重新解释；无 shell |
| 静默卸载 | `parse_app` 只取 UninstallString，仅 Quiet 串的非 MSI 条目命令为空 → UI 按钮禁用（回归测试 `never_uses_quiet_uninstall_string`） |
| 误提权 | runas 仅 740 触发；UAC 由 Windows 托管，可拒绝；release 恒提权形态下通常直接 CreateProcessW 成功 |
| 等待挂死 | 深度 16、`seen` 去重（含 PPID 环单测：环不死循环）、主退出后收尾 480 轮×250ms≈120s 上限 → Timeout 结论，UI 提示人工检查 |
| 父进程退出/收养丢目标 | `seen` 跨轮持久化（单测模拟 100/200 退出后 300 PPID 断链仍在等待集） |
| runas 路径 PID 反查失败（pid=0） | wait_tree 检测 root=0 退化为"仅等主句柄"直接 Exited——避免把全部 PPID=0 顶层进程误判为后代（评审前自查发现并修复，代码注释在案） |
| PID 复用 | 已知限制：root 退出后 PID 恰被复用且新进程持续生子 → 最坏结论为 Timeout（保守文案，不触发任何进程/文件动作），不会误杀 |

| 并发双卸载 | state.uninstalls 非空即拒绝；完成/出错/取消路径均 remove；锁中毒→失败关闭（Err/false），不静默放行 |
| 句柄/布局 | ProcessInformation Drop 双关（runas 路径 thread=null 有非空守卫）；快照 RAII；STARTUPINFOW 编译期尺寸断言 |
| 红线 6 | 生产路径无 `unwrap()`/`expect()`/`panic!()`（mod.rs 守卫性 unwrap 在评审前自查中已改写为 let-else 分支）；FFI 缓冲定长 2048/568，UTF-16 长度按 API 返回值切片 |
| 前端误操作 | 无命令条目按钮置灰；确认面板边界三条；停止等待旁注"不关闭卸载器、不强制结束"；事件按 txId 过滤（首帧采纳防竞态）；组件卸载清理监听/定时器 |

### 残留风险（如实声明，不掩盖）

1. **PID 复用**：最坏 Timeout 保守结论（见护栏表），不引发错误动作。
2. **待重启名称回退匹配**：`app.name` 出现在任意 Pending 条目即计 reboot_pending——
   仅在"键仍在"时影响文案分类（Removed 优先级最高），短名程序存在误标可能；
   R27-3 做残留候选时将改为 InstallLocation 精确前缀为主、名称匹配仅审计提示。
3. **WAIT_ROUNDS=480 固定值**：极端慢的卸载器子进程收尾超 120s → Timeout 文案；
   用户可再次观察列表，条目实际消失即已成功（判据不依赖等待结论）。
4. 本任务不含 R27-3 残留扫描/隔离；结果页对"安装目录仍存在"仅展示标签，不提供删除入口。
