## 二、破坏面清单

本次改动新增的"能删文件/移动文件/改属性"代码路径（逐条）：

1. **`store::move_into_quarantine`（同盘）** → `fs::rename(src, target)`：把用户文件**移入**隔离区。源路径被移除。
2. **`store::move_into_quarantine（跨盘）`** → `copy_verify_delete`：`fs::copy` → `fs::remove_file(src)`。**删除源文件**前必须通过目标 sha256 == 源校验，否则中止且不清源。
3. **`store::sha256_file`**：只读，无破坏。
4. **`mod::ensure_quarantine_root` / `set_hidden_system`**：`create_dir_all` + `SetFileAttributesW` 设 hidden+system，不改用户数据。
5. **白名单新增哨兵**：只增匹配规则，不改删除路径。
6. **`manifest::update_entry_state` / `clear_manifest`**：仅重写 `manifest.jsonl` 文本，不动文件本体；`clear_manifest` 为 P3-06 预留未接线（标注 `#[allow(dead_code)]`）。
7. **IPC 层无新增破坏性命令**：`quarantine_*` 命令仍是 stub（P2-02 填充）。

**安全网（本次新增破坏面的既有前置护栏）**：
- 白名单 §2.6：隔离区整棵子树被 `is_whitelisted` 拦截，绝不进入通用清理删除路径；
- 目录哨兵已顶进 `safety/whitelist`，不经 `walk`/`mft` 通用清理；
- 任何破坏性调用需先经 `safety/grade` 与调用方级联的 token/journal（P2-04 才接 journal，当前无生产调用方）。
