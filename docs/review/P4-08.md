### H3 `maxAgeDays`/`minSize` per-include 实现原是虚假声明

## 2. 破坏面清单（评审重点）

本批**新增的"能删/能移动"路径**与语义变化：

1. **H1 是"扩大扫描面、收窄删除面"的变更**：
   - 扫描面扩大：dup/large/cache/privacy（🟡/🔴 quarantine 去向）现在可以**列出** §2.4 用户核心目录下的文件——但仅列出（只读扫描）；
   - 删除面**未扩大**：这些候选去向全部是 quarantine（隔离区 14 天可还原 + 报告页逐项确认）；**direct/recycle 候选在 §2.4 内仍被 preflight 整树拦截**（用户文档绝不进直清/回收站）；
   - **restore 放行 §2.4 是"恢复数据"而非新增删除**：把隔离文件还原回用户文档目录——还原操作本身不删任何东西（冲突兜底不覆盖）；
   - 攻击面复核：伪造 manifest 把文件"还原"到 Documents——H1 前后都可行（H1 前被 §2.4 误拦属过度保护），T-2 ①②④（根内/sha256/父链 reparse）不变，威胁模型未弱化；
2. **H2 修复扩大守卫覆盖**（多 guard 全生效）——只会让清理**更保守**（更多情况整类阻止）；
3. **H3 收窄清理面**（maxAgeDays 生效 = 更少文件进候选）——"比声明更激进"的过度清理面收敛到规则承诺；
4. **M1 收窄执行面**（intent 写失败不动手）；
5. **M2/M3/M5/M6 不改变删除行为**（原子写/域拒/云跳过/锁容错）。
