## 二、破坏面清单

本次改动新增的"能删文件/移动文件/改注册表/杀进程"代码路径（逐条）：

1. **`execute.rs::delete_direct`** → Win32 `DeleteFileW`：**永久删除文件**（绕过回收站，不可恢复）。
2. **`execute.rs::apply_one` → `cleaner::recycle::delete_to_recycle_bin`** → `SHFileOperationW`：把文件移入系统回收站（可恢复）。
3. **`execute.rs::apply_one` → `quarantine::move_into_quarantine`** → 移入隔离区（P2-01 store，复用既有护栏：同盘 rename/跨盘 copy+hash 校验后删源）。
4. **`execute.rs` 调用 `Journal::intent/result`**：仅写 journal 文本，不动文件本体。
5. **`execute.rs` 调用 `logging::audit::record`**：仅追加日志文本，无破坏。
6. **`guard/process.rs`**：只枚举读取进程快照，无终止进程操作（只读探测）。
7. **`commands.rs::clean_execute`**：后台线程调度删除目标 + 校验 🔴 无 token 拒绝；`clean_cancel` 仅置位取消令牌，无直接破坏。
8. **契约加性变更**：新增事件，不改既有命令签名，不新增删除路径。

**安全网/门禁维（本次破坏面对应的前置护栏）**：
- **SAFETY §3 先日志后动手**：每个文件 `intent` 先于操作、`result` 后于操作，O_APPEND 只追加；journal 不可用 → 整体中止不删。
- **R02 分级去向**：🟢 direct/recycle 可直清，🟡/🔴 一律进隔离区（不新增任何 🔴 删除路径面）。
- **M0 🔴 语义落地**：`clean_execute` 含 Red 项而 `confirmToken` 缺失/空 → 拒绝（`is_none_or` 判定）。
- **进程守卫（R23 一语义）**：类目 guard 进程运行中 → 整类 Skip 不做半清。
- **白名单不可碰**：送入本引擎的 target 已先经扫描链路 + safety 分级过滤（P1 完成），本任务不绕过该层。
- **单文件失败不中断**：记 `ok=false` + detail，汇总到 report 由前端展示。
- **可恢复语义**：direct=硬删、recycle=可回收站还原、quarantine=隔离区 14 天可还原（SAFETY §4.5 语义区分）。

关键边界用例（SAFETY §6.3 之 1–7 起底，已覆盖）：
- **journal 恢复/孤儿检测**：`journal` 单测 `failed_result_is_not_orphan`（有 result 的 intent 不算孤儿）→ 代码路径绿；`execute` 测后断言 `detect_orphans().is_empty()`。
- **中断回滚（单文件失败不中断）**：`missing_source_is_failure_not_crash`（源缺失 → fail=1 不 panic）+ 整体报告汇总。
- **进程守卫阻止整类**：`guard_blocks_whole_category`（设不会运行的进程名验证不误伤，空 guard 不阻止）。
