## 2. 白名单匹配逻辑变更逐条评审

| # | 变更 | 影响方向 | 说明 |
|---|------|---------|------|
| 1 | `..` 段文本化弹栈（双侧） | **只收紧**：声明 `a\b\..\guard` 归一为 `a\guard` 后命中候选 | 旧行为：含 `..` 的声明永不匹配 → 保护静默丢失（安全审计 T-4） |
| 2 | `.` 段/空段跳过（双侧） | 只收紧 | 同上，`a\.\guard` 现在命中 |
| 3 | 逐段剥尾随点/空格（双侧） | 只收紧 | Win32 创建路径时吃掉段尾点/空格：`guard.keep.` 与 `guard.keep` 在 NTFS 语义同名；任一侧书写差异不再失配 |
| 4 | 8.3 短名声明 → `GetLongPathNameW` 展开并存（仅 XML 附加根，加载时） | 只收紧 | 旧行为：短名声明的根对长名候选永不匹配；展开失败（文件不存在/卷禁 8.3）保留原形式，行为不劣化 |
| 5 | 段级向量匹配替代字符串前缀 | 中性 | 语义与原段级匹配一致（`C:\a` 不误配 `C:\ab` 保持），仅实现载体变化 |

**不放宽论证**：①-④ 全部是"让两侧更容易对上"（更多候选被白名单拦下），
扫除候选只减不增；⑤ 等价重构。常量根（`collect_roots`，env 来源）未做短名
展开（env 值 canonical，非攻击面），已注释。

**单测覆盖**：`t4_dot_and_dotdot_segments_resolve`、
`t4_trailing_dot_or_space_segments_normalize`、
`t4_short_name_declaration_expands_to_long`（卷禁 8.3 自动跳过）、
既有 11 例全回归（含正斜杠不绕过、段级不误配兄弟路径）。

## 3. golden-misdelete-test 全量重写要点

1. **fixture 生成器**：`build_golden_tree` 声明式五族 132 文件（safe 48 / temp 43 /
   dup 21 / red 13 / 结构件）+ 预期清单（must_keep 56 / must_sweep 64）；
2. **三档分母非平凡**：黄/红档 target 内各放白名单守卫（`dup_y`/`red_r`）——
   守卫失效直接进对应档误删率（黄档 1 项 = 1.8% < 2% 门槛，故另有逐 tag
   `guards_swept` 断言兜底，红档 0 容忍）；
3. **清理阶段（新增，SAFETY §6.1"跑扫描+清理"）**：绿/direct 项走真实
   `resolve_targets → execute`（journal/preflight/DeleteFileW/审计全链路，
   数据根注入沙箱）；盘面核对：must_keep 缺失 = 真误删（必须为空）、合法项
   已删、只读/长路径按 Windows 语义优雅失败留盘（单独断言）、journal 零孤儿；
   黄/红去向隔离区（真实卷根不可注入）→ 仅扫描期度量（头注释已声明边界）；
4. **T-4 守卫**：白名单以旁路形式声明（`.` 段/`..` 段/尾随点/8.3 短名），
   断言四形态守卫零被扫（本机实测四形态全 protected，短名可用=true）。
