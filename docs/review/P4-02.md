## 2. 破坏面清单（本任务改动触及的"能删/能移动文件"路径）

本任务**未新增破坏能力**，反而收紧了四道既有破坏路径（全部为"由放行改为拒绝"方向）：

1. `cleaner::execute::apply_one`（删除/回收/移入隔离区）：新增 preflight 前置闸门——白名单命中 / 祖先 reparse / size·mtime 漂移 → 拒绝执行（原：仅信任扫描期结论）。
2. `quarantine::restore_one`（隔离区→原路径移动）：新增四重校验——伪造 manifest 的越界移动/内容替换/系统目录目标/junction 重定向全部拒绝（原：盲信 manifest 字段）。
3. `quarantine::ensure_quarantine_root`：隔离区根为 junction/非目录 → 拒绝创建使用（原：不检查）。
4. `ipc::clean_execute` 事务入口：规则加载失败 → 整个事务拒绝（原：fail-open 继续执行且守卫失效）。

新增进程行为：`guard::instance` 互斥量 + 第二实例**退出自身进程**（`std::process::exit(0)`，仅当检测到已有实例；窗口激活为 best-effort）。无注册表/网络新增面。

红线对照：#2 先日志后动手——preflight 在 journal intent 之后、动手之前执行，拒绝时 result ok=false 落 journal+审计；#3 白名单不可碰——preflight/restore 双侧重跑 `is_whitelisted`；#8 🔴 灰禁——未触及。
