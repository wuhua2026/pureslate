## 2. 破坏面清单（本任务改动触及的"能删/能移动文件"路径）

本任务**未新增破坏能力**，全部为"由盲删改为校验后删"的收紧：

1. `quarantine::lifecycle::run_pass_at_root`（启动时自动执行的到期硬删）：新增根内/非 reparse/sha256 三重校验；任一不过 → 跳过删除 + fail 审计 + 条目保留 `quarantined`（原：直接 `remove_file` 任意 `quarantine_path`）。
2. `quarantine::lifecycle::purge_at_root`（用户「确认清空/释放最早批次」硬删，token 后）：同上三重校验（原：同盲删）。
3. `quarantine::restore::restore_one`（隔离区→原路径移动）：根内判定由字符串前缀升级为段级归一，`..`/ADS/尾随点形态不再可通过（原：`C:\...\..\Windows\x` 能通过前缀比较）。
4. 失败路径行为变化：校验失败不再把 manifest 行置 `purged`；文件删除失败也不再置 `purged`（此前会误标已清除）。这使"重复尝试/人工介入"成为可能，代价是每次启动可能重复写 fail 审计。

新增进程行为：无。注册表/网络/进程创建均无新增面。

红线对照：#2 先日志后动手——purge 前校验在删除前执行，拒绝即写审计（可追溯）；#3 白名单不可碰——本任务只收紧隔离区内部删除，未触碰白名单语义；#8 🔴 灰禁——未触及。
