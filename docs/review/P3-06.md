## 2. 破坏面清单（本任务新增的"能删文件"代码路径）

1. **到期自动清除**（`lifecycle::run_pass_at_root` §1 段）：`expires_at ≤ now` 的 quarantined 条目 → `fs::remove_file(quarantine_path)` 硬删 + manifest state→purged + 审计 `auto_purge`。
   - 触发点：应用启动钩子 + 每次 `quarantine_list`/`quarantine_status`。
   - 约束：只删 `.pureslate-quarantine` 根内、manifest 登记、且**用户清理时已被告知保留期**（14 天默认，settings 7–30）的文件；文件缺失视为已收敛（幂等）。
   - 可追溯面：manifest 行（sha256/原路径/移入时间）在删除前后始终保留为 purged 行——**删除前记录已存在**（红线 #2 语义：journal 的等价物即 manifest 持久行 + 审计）。
2. **手动硬删**（`lifecycle::purge_across`）：按 id 硬删 + state→purged + 审计 `purge`。`confirm_token` 为空 → 全部拒绝（🔴 语义兜底，UI 侧 ConfirmTokenModal 逐字输入）。用于"确认清空"与超限"释放最早批次"。
3. **restored 行清理**（`manifest::prune_restored_before`）：只删 manifest **行**（文件早已还原），不动任何文件系统对象。
4. **容量超限不删除**：`over_quota` 仅产出建议 id 集，删除必须经路径 2（用户 + token）——无静默丢弃。

不变式：隔离区根仍由 `quarantine_root_of` 哨兵限定（白名单 §2.6 挡住通用清理）；硬删只作用于 manifest 中 `state=quarantined` 且 `quarantine_path` 位于隔离区根内的条目（路径由本应用生成）。
