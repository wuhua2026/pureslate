# PureSlate 代码审计与处置记录（2026-10-18）

> **来源**：2026-10-18 对公开仓库 `wuhua2026/pureslate` v0.2.1（main `77ac017`）的一次独立代码级审计
> （3 路并行静态分析 + Lead 独立复核 + 本机实测）。审计为只读，未改动被审快照。
> **本文件写入仓库的目的**：把"问题 + 处置决定 + 现状"固化为可追踪记录，避免"宣称 > 落实"。

## 0. 三句话结论

1. 工程本体真实：代码规模、测试、CI、发布资产哈希、规则 XML、手写 Win32 FFI 均可核，不是套壳项目。
2. 信任链缺口集中在"用户可写状态 → 提权进程执行"：隔离区 purge 盲信 manifest（已修），规则 `disposition` fail-open（已修），发布版恒提权放大了这两条的后果。
3. 文档质量高于同类项目，但存在系统性"自我验收当作外部证据"：不可复现证据、被 gitignore 的死链、未实现的安全宣称（本次已按实际修正口径）。

## 4. 接受为设计边界（不修）

1. **恒提权（`requireAdministrator`）**：MFT/卸载等能力需要管理员；代价是 UAC 门槛与权威放大。若未来改为"按需提权"需产品级重构（R32 评估，不在本批）。
2. **规则包投毒仍需用户交互确认**：不存在自动下载执行新二进制的路径；一键清理也只清 🟢 安全项且需点击确认——不构成静默执行。
3. **令牌不绑定操作/目标集**：定位是"防误点"而非防被控渲染进程（CSP 为 `self`，无远程内容）。
4. **`docs/verify/*.json` 一次性人工产物**：不伪造、不删除，但不再作为可复现门禁宣传。
5. **手写 Win32 FFI 的 unsafe 面**：是"零依赖/小体积"的代价，记录为已知风险，持续要求 unsafe 注释与边界校验。
